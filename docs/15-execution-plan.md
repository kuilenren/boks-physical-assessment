# 15 落地执行方案

> **文档状态：**可执行
> **制定基线：**2026-08-02（Asia/Shanghai）
> **上游文档：**差距清单见 [14-market-standard-audit.md](14-market-standard-audit.md)，与本方案配套使用
> **目标：**把 BOKS 从"可演示 MVP 闭环"推进到"达到市场成熟小程序/App 工程质量、可正式对外交付"的状态
> **原则：**标准先于算法、原始值与解释分离、筛查不冒充诊断、监护人可控、不把自动抓取当作自动生效、训练建议可执行

---

## 1. 方案目标与范围

### 1.1 目标

| 编号 | 目标 | 验收摘要 |
| --- | --- | --- |
| G1 | 真实监护人身份与权限体系 | 微信/手机号登录；生产无 dev-login；越权矩阵单测通过 |
| G2 | 生产级数据与文件存储 | PostgreSQL RLS/加密/迁移/备份；对象存储私有桶；删除闭环 |
| G3 | 经核验的专业数据 | 正式评分表 + 双人审核发布；历史报告版本锁定 |
| G4 | 真实体态能力或明确边界 | 真实质量门禁；无模型则收缩宣传 |
| G5 | 受控 AI 咨询 | 安全策略 + RAG + 拒答；无幻觉数值 |
| G6 | 达到市场成熟体验 | 三态统一、动效、分享、埋点、异常上报、无障碍 |
| G7 | 后台与运营 | 管理后台 UI、审核工作台、删除工单台 |
| G8 | 工程化与运维放行 | 超时/幂等/分页、测试、监控、告警、备份恢复、上架材料 |

### 1.2 范围边界（持续不做）

- 医疗机构合作、人工转诊、医疗诊断闭环。
- 学校/机构班级管理、订阅、外部教师端。
- 儿童原图进入广告、画像或默认模型训练。

## 3. 详细阶段计划

### 阶段 1：身份、权限与会话（1.5—2.5 周）

**目标：**真实监护人身份，去掉开发旁路。

| 编号 | 任务 | 端 | 详细做法 |
| --- | --- | --- | --- |
| A1 | 微信登录 | 小程序+API | `wx.login` → `code2session` → 绑定/创建 guardian → 返回 access/refresh |
| A2 | 手机号登录 | App+API | 验证码、频控、设备指纹摘要、风控阈值 |
| A3 | 会话体系 | API | access 短时 + refresh 轮转；登出吊销；多设备列表；恢复一致性 |
| A4 | 家庭成员模型 | API/DB | `family`、`guardian`、`membership`、`role` |
| A5 | 授权中间件 | API | 儿童资源按 membership 校验，单测覆盖越权矩阵 |
| A6 | 关闭 dev-login | 全端 | 生产构建剔除自动 dev-login；CI 检测字符串与开关 |
| A7 | 首次同意流 | 双端 | 隐私政策/儿童信息/分项目强阻断同意 |

**验收：**

- 无 token 访问业务接口 401；生产镜像不含可用 dev-login。
- 家庭 A 无法读写家庭 B 儿童。
- 登录/登出/刷新/多设备单测通过。

### 阶段 2：生产数据层与文件存储（2—3 周，与阶段 1 并行）

**目标：**可备份、可并发、可删除证明。

| 编号 | 任务 | 详细做法 |
| --- | --- | --- |
| D1 | PostgreSQL 正式模型 | 按 `docs/08` 落地表结构、约束、索引；引入迁移版本表（如 `boks_migrations`） |
| D2 | RLS 落地 | 对家庭/儿童/报告等表启用行级安全策略 + 应用角色；全量越权矩阵测试 |
| D3 | 敏感字段加密 | 出生日期/昵称/手机号 `_ciphertext` 列；KMS 密钥轮换 |
| D4 | 对象存储 | 预签名上传、MIME/大小/校验和校验、私有桶、服务端加密、TTL |
| D5 | 图片生命周期 | 体态原图 TTL、删除任务、失败重试、删除证明 |
| D6 | 导出/删除编排 | 导出异步打包为文件；删除覆盖 DB+对象+缓存并写证明 |
| D7 | 备份 | 日备 + WAL；恢复演练一次并记录 RTO/RPO |
| D8 | Redis | 会话黑名单、验证码、限流、异步任务队列 |
| D9 | 仓储层重构 | 去掉业务对 `demo-store` Map 的依赖，引入 repository 接口 |

**验收：**

- 压测基础读写不丢数据；删除儿童后对象存储无原图残留。
- 备份恢复演练成功并记录 RTO。
- 所有写接口支持幂等键，重复提交不产生重复任务。

### 阶段 4：体态拍摄与观察能力（3—6 周）

**目标：**要么交付真实观察能力，要么收缩产品宣传。

#### 路径 A（推荐上线最小集）

1. 完整拍摄引导与**真实质量门禁**（清晰度、完整人体、四视角齐全、遮挡）。
2. 质量失败只给重拍建议，不给风险等级。
3. 通过后生成"拍摄合格证明 + 家庭姿态习惯建议"，明确非测量、非诊断。
4. 原图加密存储与家长删除。

#### 路径 B（完整观察）

在路径 A 上增加关键点模型、对称性/体态观察指标、复测对比、低置信度策略与专业评审。

| 编号 | 任务 | 优先级 |
| --- | --- | --- |
| P1 | 预签名直传与进度 UI | P0 |
| P2 | 实时/近实时质量检测 | P0 |
| P3 | 重拍原因结构化 | P0 |
| P4 | 报告模板与限制声明 | P0 |
| P5 | 关键点与观察指标 | P1 |
| P6 | 复测对比 | P1 |
| P7 | 模型评估集与回归 | P1 |

**验收：**

- 无模型时产品文案不得承诺"立体分析出风险/疾病"。
- 有模型时通过分层评估门槛，且永不输出 Cobb 角/诊断。

## 4. 跨端技术方案要点

### 4.1 网络层统一（阶段 1/7）

- 小程序与 App 共用一个 HTTP 客户端能力规范：`timeout`、指数退避重试、`AbortSignal` 取消、`Idempotency-Key` 自动生成、`X-Trace-Id` 透传、分页 `page_token`。
- 生产 baseURL 从编译期注入，禁止占位域名；CI 检测 `api.example.invalid`。生产域名：`https://www.boks-ai.com.cn/v1`。
- 会话：access 短时 + refresh 轮转；登出清理本地 token 与儿童选择。

### 4.2 数据模型（阶段 2）

- 停止"整 JSON 双写"，改为正式关系模型 + 领域仓储。
- 儿童、报告、体态、训练、对话、知识、审计均按 `docs/08` 建表。
- 所有写接口幂等；删除编排为异步任务。

### 4.3 评分引擎（阶段 3）

- 规则 DSL 白名单操作；`standard_version_id + scoring_table_version + algorithm_version + rule_evaluation_trace` 五元组锁定。
- 客户端不得提交 `score/weight/level`；服务器查表 + 附加分 + 分档。

### 4.4 体态流水线（阶段 4）

- 客户端：拍摄引导 + 本地尺寸预检 + 预签名直传 + 上传进度。
- 服务端：MIME/大小/校验和 → 质量门禁（真实模型或规则）→ 关键点（可选）→ 观察指标 → 报告。
- 任一必需视角未过，`analysis` 不得返回风险结论。

### 4.5 AI 咨询（阶段 6）

- `services/ai`：FastAPI + 受控 provider；安全策略服务（意图分类 + 红旗库）；RAG 只读已发布快照；拒答模板；审计日志不含原文。
- 双端：流式输出、引用卡片、急症提示、转人工工单。

### 4.6 管理后台（阶段 8）

- Next.js + TypeScript + Ant Design（`docs/04` 选型），接入既有 API 契约与 MFA。

## 6. 风险与依赖

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 正式评分原文获取延迟 | 阶段 3 阻塞 | 收缩首发范围为"体测记录+家庭训练+拍摄合格档案" |
| 姿态模型未就绪 | 阶段 4 阻塞 | 走路径 A，收缩宣传 |
| dev-login 流入生产 | 数据泄露 | 构建门禁 + 启动自检 + CI 字符串检测 |
| 删除不彻底 | 违法与信任崩溃 | 删除证明 + 定期扫描 |
| 咨询幻觉/诊断 | 安全事件 | 检索白名单 + 强制拒答 |
| 小程序/商店审核驳回 | 延期 | 提前隐私指引与权限申请文案 |
| 双端契约漂移 | 返工 | OpenAPI 单一事实源 + 契约测试 |
