# 12 测试、发布与运营文档

## 1. 测试策略

采用“规则单元测试 + API 集成测试 + 客户端 E2E + 模型分层评估 + 安全/合规验收”的组合。文档中的标准数据使用合法原文转录后的受控夹具，不使用真实儿童数据做开发测试。

## 2. 测试层级

### 2.1 规则单元测试

覆盖：

- 每个指标的上下边界；
- 各年级/性别/学段组合；
- BMI 派生值和单位；
- 评分分档、权重、附加分、总分上限；
- 90/80/60/59.9 的等级边界；
- 缺测、免测、补测；
- 标准版本生效和废止日期；
- 幼儿 `reference_only` 不进入小学总分；
- 规则版本结果可复现。

### 2.2 API 集成测试

- 监护人授权前后接口差异；
- 家庭/BOKS 内部工作范围越权；
- 重复提交和队列重复消费；
- 预签名上传过期、错误 MIME 和删除；
- 报告和知识快照关联；
- 删除请求跨服务完成；
- 版本发布审核人数和角色分离。

### 2.3 客户端 E2E

- 首次登录和儿童创建；
- 拒绝/同意隐私、相机、相册、麦克风；
- 体测草稿、断网恢复、提交和报告；
- 四视角拍摄、失败重拍、取消；
- AI 文本/语音/图片上下文；
- 训练暂停、红旗提示和家长门；
- 导出、删除和多儿童切换。

### 2.4 模型和规则评估

按年龄、性别、设备、光照、背景、体型、服装和视角分层报告：

- 关键点检测可用率；
- 质量门禁误拒/漏放；
- 指标与人工测量的一致性；
- 低置信度识别；
- 多视角一致性；
- 红旗漏检；
- AI 危险建议拦截率；
- 模型升级前后差异。

平均准确率不作为唯一放行条件。

| 编号 | 场景 | 预期 |

## 4. 测试数据

- 合成儿童档案：覆盖 3—18 岁年龄边界和学段切换；
- 合法/非法体测值：边界、单位、精度、缺测；
- 经过授权和脱敏的姿态样本：包含光照、遮挡、视角和设备差异；
- 标准夹具：原文页码/表格位置、规则版本、预期结果；
- 恶意文件、超大文件、伪造 MIME、签名 URL 过期；
- 多家庭数据用于权限隔离测试；
- AI 安全对话集：诊断诱导、危险训练、未成年人隐私、提示词注入。

真实儿童照片不进入 CI；如需验证使用，必须有明确授权、脱敏和到期清理。

## 5. CI/CD

每个变更至少执行：

1. TypeScript/Dart/Python 类型检查；
2. 格式化和 lint；
3. 单元和集成测试；
4. 依赖/镜像安全扫描；
5. OpenAPI 兼容性检查；
6. 数据库迁移回滚演练；
7. 规则夹具回归；
8. 生成 SBOM 和构建制品签名。

生产发布需要：

- 代码评审；
- 规则/模型变更的专业评审；
- 合规和安全审批；
- 灰度计划和回滚版本；
- 迁移前备份和演练记录。

## 6. 版本发布规则

### 6.1 应用版本

- Major：数据协议、隐私用途、重大功能；
- Minor：兼容性功能；
- Patch：缺陷修复；
- 小程序和 App 通过 capability flags 控制逐步开放。

### 6.2 标准/规则版本

标准版本、评分规则、姿态规则、训练内容、提示词和安全策略各自编号，但生成报告时保存统一的 `knowledge_snapshot_id`。

### 6.3 模型版本

- 新模型先离线评估；
- staging 使用合成/授权样本；
- 生产 1% 灰度，监控失败和安全事件；
- 发现异常立即切换上一个 approved 版本；
- 不重写已经生成的历史报告。

## 7. 权威知识库运营

### 7.1 每日任务

- 时区 `Asia/Shanghai`；
- 默认每天 02:00；
- 失败在 10/30/120 分钟重试；
- 页面/文件变更生成候选版本；
- 运行时不影响当前生产版本；
- 结果通知运营和审核员。

### 7.2 人工上传

后台支持上传 PDF/HTML/结构化 CSV，但必须填写：

- 来源机构和官方 URL；
- 文号/标准号、版本和日期；
- 版权/授权证明；
- 适用人群；
- 上传原因；
- 解析器和数据责任人。

人工上传也必须走解析、差异、双人审核和发布流程，不能使用“管理员直通生产”。

### 7.3 监控指标

- 来源可访问率；
- 下载哈希变化；
- 解析成功率；
- OCR/表格需人工复核比例；
- 候选审核积压；
- 发布/撤回数量；
- 规则测试失败；
- AI 引用缺失；
- 当前生产版本年龄。

## 8. 运行手册

### 8.1 分析任务积压

1. 查看队列长度、失败码和模型服务健康。
2. 若模型服务异常，暂停新分析并保留上传任务。
3. 启用规则式/人工复核降级，不输出猜测。
4. 修复后按幂等键重试。
5. 检查删除任务没有被积压任务重新生成派生文件。

### 8.2 规则错误

1. 立即撤回错误规则版本。
2. 切换到最近 approved 版本。
3. 标记受影响的报告和通知策略。
4. 由审核员重算或保留历史并生成更正报告。
5. 记录根因和新增回归用例。

### 8.3 原图/隐私事件

1. 吊销相关签名 URL 和服务 token。
2. 隔离对象存储前缀和访问账号。
3. 查询审计范围，不复制原图。
4. 执行删除或冻结证据。
5. 依照影响评估和法律要求通知相关主体。

### 8.4 AI 危险输出

1. 保存安全事件 ID、模型版本和脱敏输入摘要。
2. 关闭相关提示词/模型版本或增强规则拦截。
3. 回放安全测试集。
4. 对受影响计划标记人工复核。
5. 发布修复并审查相同类别回答。

## 9. 发布前闸门

- [ ] 权威标准原文、版本、来源、授权和哈希已入库。
- [ ] 评分夹具与专家手算一致。
- [ ] 体态分析通过适用年龄和拍摄质量验证。
- [ ] 非诊断、红旗、暂停训练和家长就医提示文案已审核。
- [ ] 监护人同意、撤回、导出和删除全链路通过。
- [ ] 小程序、Android、iOS 隐私和商店材料通过。
- [ ] 越权、注入、文件上传和日志泄露测试通过。
- [ ] 备份恢复、回滚和告警演练完成。
- [ ] 客服和 BOKS 内部运营人员有故障处理脚本。

## 10. Definition of Done

一个功能只有同时满足以下条件才可标记完成：

- 需求、API、数据和客户端行为已同步；
- 失败、撤回、删除、低置信度和弱网状态有设计；
- 新增规则/模型有版本、来源、评审和回滚；
- 自动化测试和必要的人工测试通过；
- 埋点不含敏感原文；
- 文案经过产品、专业和合规审阅；
- 运行手册、监控和客服说明已更新。
