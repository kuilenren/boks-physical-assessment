# 01 产品需求文档（PRD）

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | BOKS智能体测体态分析 |
| 产品形态 | 微信小程序、Android App、iOS App、BOKS 内部管理后台 |
| 目标人群 | BOKS 自有的 3—18 岁学生及其监护人；BOKS 内部内容、知识库和安全审核人员 |
| 版本 | PRD-0.1 |
| 研究基线 | 2026-08-01 Asia/Shanghai |
| 产品边界 | 体测评分、姿态观察、运动训练辅助；不提供疾病诊断和处方治疗 |

## 2. 背景与问题

家长和 BOKS 课程团队通常能拿到分散的体测数字，却难以回答以下问题：

- 当前分数由哪个国家标准、哪个年级和性别表计算；
- 哪些指标拉低了总分，下一阶段应先改善什么；
- 姿态照片是否满足拍摄条件，前后左右是否可以比较；
- 训练能否在家完成，如何控制强度，出现什么情况应停止；
- 规则标准更新后，历史报告是否应重算；
- 未成年人照片和健康结果由谁查看、保存多久、如何删除。

BOKS 将测量、标准、解释、训练和复测串成可追溯的闭环。

## 3. 产品目标

### 3.1 业务目标

1. 让家长在 10 分钟内完成一次体测录入，并获得可解释报告。
2. 让家长在 5 分钟内完成四视角拍摄质量检查，必要时重新拍摄。
3. 让报告中的每项建议都能追溯到标准、规则或专业内容版本。
4. 让 BOKS 内部管理员无需发版即可审核和更新知识库、训练内容和文案。
5. 将健康风险提示、监护人同意、删除和审计作为默认流程，而不是上线后补丁。

### 3.2 用户价值

| 用户 | 核心价值 |
| --- | --- |
| 家长 | 看到孩子当前能力、变化趋势和可执行的家庭训练 |
| 学生 | 看到易懂的目标、徽章和训练反馈，不被负面标签定义 |
| BOKS 内部课程/内容人员 | 维护动作、训练计划和家长可读文案 |
| 专业审核员 | 维护标准来源、规则版本、训练内容和风险文案 |
| 运营人员 | 监控任务、数据质量、模型版本和用户反馈 |

## 4. 用户与权限

### 4.1 角色

- **访客：**只能查看产品介绍和隐私说明。
- **监护人：**创建儿童档案、授权照片分析、录入数据、查看/删除报告和训练记录。
- **儿童/学生：**在监护人授权下查看计划、完成打卡；不独立管理敏感数据。
- **BOKS 内部内容人员：**维护已发布动作和训练文案，不能默认查看原始照片。
- **知识库审核员：**审核来源、规则、训练文案和发布版本。
- **BOKS 内部运营/安全管理员：**处理家长请求、审计、撤回、删除和紧急下线。
- **安全/审计管理员：**查看审计事件，不默认查看原图和健康详情。
- **平台超级管理员：**执行紧急下线、回滚和法定数据请求。

### 4.2 权限原则

采用 RBAC + 数据范围（家庭、BOKS 内部工作范围）+ 敏感字段策略。内部角色权限不能绕过监护人授权；内容和运营人员默认不能看到原始照片、聊天全文或身份凭证。

## 5. 核心用户旅程

### 5.1 家长体测旅程

1. 微信登录或 App 登录。
2. 阅读隐私政策和儿童数据说明，监护人确认。
3. 创建儿童档案：出生日期、性别、学段/年级、身高、体重、健康禁忌。
4. 选择标准版本；系统根据学段、年级、性别展示允许的指标。
5. 输入原始值，实时校验单位、范围、精度和缺测状态。
6. 服务端以锁定的标准版本评分，返回原始值、单项分、权重、附加分和总分。
7. 生成报告，展示“数据来源—计算—建议”的链路。
8. 选择训练目标，生成 4—8 周计划；首次训练前确认安全问卷。

### 5.2 家长体态旅程

1. 进入体态分析，先完成适用范围和风险提示阅读。
2. 选择儿童档案并确认监护人授权、照片用途、保留期限和删除方式。
3. 观看拍摄示例，按前/后/左/右顺序拍摄或上传。
4. 客户端执行分辨率、光照、遮挡、姿态、距离和背景质量检查。
5. 质量不合格时只提示具体原因，不继续生成误导性结果。
6. 服务端或端侧模型提取关键点，计算可解释的姿态观察指标。
7. 生成非诊断性报告，标明置信度、限制和家长复拍/就医提示情形。
8. 根据观察指标生成安全训练计划，出现红旗症状则暂停计划并提示就医。

### 5.3 BOKS 内部审核旅程

1. BOKS 内部人员登记或上传权威来源原文。
2. 解析标准元数据、评分表、姿态规则和训练内容。
3. 专业审核员核对原文、适用范围、版本和安全文案。
4. 发布管理员生成知识快照，必要时回滚或撤回。
5. 家长端只读取已发布版本，内部人员不能直接改写家长历史报告。

### 5.4 知识库更新旅程

1. 定时任务发现官方页面、公告或文件变更。
2. 下载原文并保存 URL、时间、HTTP 元数据、文件哈希和解析状态。
3. 解析出标准元数据、指标、评分表和适用范围，生成候选版本。
4. 校验员逐项复核原文和结构化数据。
5. 专业审核员批准后发布；生产评分只引用已发布版本。
6. 如发现错误或撤回，执行紧急下线/回滚并保留历史报告。

## 6. 产品原则

- **儿童友好：**不用“差、畸形、问题儿童”等标签；分数以行动建议为中心。
- **证据透明：**报告显示标准名称、版本、生效日期和解释限制。
- **安全优先：**不鼓励疼痛训练、强力扳压、牵引或自行矫形。
- **可复测：**提醒同一时间、同一设备/场地条件，比较前先检查测量一致性。
- **可恢复：**服务失败不丢失用户草稿；报告生成失败要显示明确状态。
- **版本不可变：**已发布规则不可原地覆盖，必须生成新版本。

## 7. 需求范围

### 7.1 P0 功能

| 编号 | 需求 | 验收摘要 |
| --- | --- | --- |
| PRD-P0-01 | 家庭和儿童档案 | 监护人可创建/编辑/删除；年龄和学段自动计算 |
| PRD-P0-02 | 标准体测录入 | 只展示当前规则允许的项目；单位和范围校验 |
| PRD-P0-03 | 体测评分报告 | 结果可追溯到标准版本，支持重新生成和历史查看 |
| PRD-P0-04 | 四视角拍摄 | 有逐视角引导、质量检测、失败原因和重拍 |
| PRD-P0-05 | 体态观察报告 | 输出指标、置信度、限制、建议复核和训练入口 |
| PRD-P0-06 | 训练规划 | 按周生成动作、频次、时长、替代动作和停止条件 |
| PRD-P0-07 | 智能咨询 | 文本问答、语音转写/播报、图片上下文；危险问题转人工/就医 |
| PRD-P0-08 | 知识库后台 | 上传、解析、审核、发布、回滚和审计 |
| PRD-P0-09 | 数据控制 | 家长授权、撤回、查看、导出、删除和保留期执行 |

### 7.2 非目标

- 不在第一版提供医学诊断、疾病分型、药物建议或医疗处方。
- 不使用普通照片计算或宣称计算 Cobb 角。
- 不根据单次体测或姿态结果自动给儿童贴不可更改的等级标签。
- 不允许未审核的网络文章直接成为评分依据。
- 不将儿童原图默认用于广告、画像或模型训练。

## 8. 关键业务规则

1. 小学至高中评分键为“标准版本 + 学段 + 年级 + 性别”，不能只按自然年龄评分。
2. 幼儿园采用幼儿专项参考和训练进步模式；幼儿综合评分表未取得合法原文前不得上线。
3. 每份报告保存输入快照、算法版本、规则版本、来源和生成时间。
4. 修改儿童出生日期、学段、性别或标准版本时，历史报告不覆盖，只能生成新报告。
5. 姿态报告必须携带拍摄质量评分、模型版本、适用年龄和“非诊断”声明。
6. 检测到疼痛、麻木、无力、夜间疼痛、明显快速变化或严重不对称时，不生成常规强化训练，转为就医提示。
7. 所有 AI 回答必须经过安全策略和知识库引用；模型不允许自行编造标准阈值。

## 9. 指标与质量门槛

### 9.1 产品指标

| 指标 | P0 目标 |
| --- | --- |
| 体测报告成功生成率 | >= 99.5%（输入合法时） |
| 报告生成 P95 | <= 10 秒，不含用户上传等待 |
| 拍摄质量反馈 | <= 2 秒返回明确失败原因 |
| 训练计划生成 P95 | <= 8 秒 |
| 家长删除请求完成 | <= 7 个自然日；系统删除动作可审计 |
| 权威规则发布 | 未经双人审核不得进入生产 |

### 9.2 模型/分析指标

上线前必须按年龄、性别、肤色/体型、设备、光照和拍摄角度分层评估：

- 关键点检测可用率；
- 拍摄质量误拒率和漏检率；
- 与人工姿态测量的一致性；
- 风险提示灵敏度、特异度和假阳性说明；
- 低置信度覆盖率；
- 训练建议安全违规率为 0。

不要把上述指标用作医疗诊断准确率。本产品不进入医疗用途范围；如未来改变产品定位，必须另行立项，不纳入当前版本。

## 10. 非功能需求

- 可用性：核心 API 月度可用性 >= 99.9%，分析异步任务可重试。
- 安全：传输 TLS 1.2+，敏感数据静态加密，密钥托管在 KMS，访问审计不可篡改。
- 隐私：监护人同意前不调用摄像头、相册和上传接口；删除后清理对象存储、缓存、派生文件和索引。
- 可观测性：每个报告和模型任务有 trace_id；不在日志写入原图、聊天原文或完整身份证号。
- 可访问性：字号可放大，颜色不作为唯一信息，语音提示有文字等价物。
- 国际化预留：日期、单位、时区、标准文本和区域配置可扩展。
