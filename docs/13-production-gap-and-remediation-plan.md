# 13 正式上线差距分析与修复完善计划

> **文档状态：**可执行  
> **分析基线日期：**2026-08-02（Asia/Shanghai）  
> **对比对象：**当前仓库可运行的家长端闭环 vs `docs/01`—`12` 定义的正式对外交付标准  
> **产品边界：**仅面向 BOKS 自有学生与家长，以及 BOKS 内部审核运营；不建设医疗机构、转诊、学校机构端或医疗诊断软件  
> **结论摘要：**当前版本已具备本地联调、演示闭环和双端构建能力，**尚不能正式对外上线**。核心阻塞项集中在真实身份认证、生产级数据与对象存储、经核验的体测标准、真实体态算法、正式 AI/语音、管理后台 UI、合规与运维放行。
>
> 第 3—4 节保留 2026-08-02 的差距分析基线；随后执行结果以第 12 节及其后续变更为准。

### 1.2 判断标准

- **已具备：**代码中可运行、有契约、本地可验证。
- **部分具备：**流程打通，但算法/存储/认证/UI 为占位或开发夹具。
- **未具备：**正式上线所需能力缺失，或仅有文档/骨架。
- **阻塞上线：**任一存在即不得对真实家长开放。

## 3. 分板块深度差距分析

### 3.1 登录、账号与权限

| 正式要求 | 当前状态 | 差距 | 影响 |
| --- | --- | --- | --- |
| 微信小程序 `wx.login` + 服务端 code 换 openid/unionid，绑定监护人 | 客户端自动调用 `/auth/dev-login` | 无微信身份，任何人可走开发登录 | **阻塞** |
| App 手机号验证码 / 设备安全登录 | Flutter 同样自动 dev-login | 无手机号、无验证码、无风控 | **阻塞** |
| 会话刷新、登出、设备列表、令牌吊销 | 7 天 UUID 会话，无刷新/登出 API | 无法回收泄露令牌 | 高 |
| 多监护人家庭、角色权限 | 单家庭单演示监护人 | 无法支持父母双账号 | 高 |
| 生产关闭开发登录 | `BOKS_ENABLE_DEV_AUTH` 默认开启；关闭时接口返回结构不规范 | 误开将导致越权演示入口 | **阻塞** |
| 管理员双人审核身份 | Header 中的 `x-admin-token` / `x-admin-reviewer` | 无正式管理员账号体系、无 MFA | 高 |

**关键代码事实：**

- 小程序与 Android 启动即自动拿开发 token。
- API 在无 Bearer 且开发开关未关闭时，回落到 `guardian-demo-001`。
- `assertChildAccess` 主要校验儿童存在，家庭隔离依赖“单家庭演示模型”，不是多租户 ACL。

### 3.2 界面与视觉

| 正式要求（`07-ui-design`） | 当前状态 | 差距 |
| --- | --- | --- |
| 首页：儿童切换器、授权状态、最近测量、下一步、今日训练 | 问候语 + 入口卡片；默认取第一个儿童 | 缺少“下一步行动”与真实任务摘要 |
| 体测录入：标准版本、测量提示、缺测/免测、草稿/提交双按钮 | 动态表单基础可用 | 缺草稿恢复、缺测状态、版本锁定提示弱 |
| 报告页：摘要、优先行动、明细、趋势图、来源与限制 | 有报告详情与基础趋势入口 | 无图表、无 PDF/图片分享、优先行动排序弱 |
| 体态拍摄：轮廓引导、脚位线、具体重拍建议 | 文字轮廓框 + 选图/拍照登记 | 无实时取景叠加、无真实质量反馈文案链路 |
| 训练页：今日任务、进度环、暂停原因、安全门 | 计划详情 + 打卡/暂停/恢复 | 动作示范、替代动作、完成反馈不足 |
| 咨询页：引用卡片、危险提示、语音入口 | 文本气泡 + 安全提示 | 无语音、无历史会话列表、无反馈 |
| 设计系统组件库 | 基础 SCSS/Flutter theme | 无统一组件库、无图标 tabBar、无插画体系 |
| 无障碍与对比度 | 主色基本符合 | 未系统验收字号、读屏、色盲友好图表 |

**交互体验共性差距：**

1. **多儿童切换不贯穿全链路。** 首页、报告、训练多处默认 `children[0]`。
2. **空状态/错误态不统一。** 部分页面有 `PageState`，部分仅 toast。
3. **离线/弱网。** 无草稿队列、无断点续传、无请求幂等键落地。
4. **结果可分享性不足。** 无报告海报、PDF、微信分享卡片。
5. **开发痕迹外露。** 首页“开发环境说明”、体态“照片登记占位”文案不可进入正式版。

## 4. 问题优先级总表

### P0 阻塞上线（必须完成）

1. **关闭并移除对外开发登录路径**，接入微信登录与 App 正式登录。
2. **完成 PostgreSQL 备份、恢复、RLS/并发演练**，保持多家庭事务隔离。
3. **完成对象存储真实 provider、生命周期、加密和四视角 E2E 验收**。
4. **导入并双人审核通过的正式体测评分表**；去掉对外 `demo_pending_review` 表述。
5. **体态：真实质量门禁 + 明确能力边界**；若无模型，不得宣传“立体分析/风险等级”。
6. **生产 HTTPS、密钥、日志脱敏、备份、监控最小集**。
7. **法务审定隐私政策、儿童信息处理规则、家长协议与非诊断声明**。
8. **小程序/Android 正式发布配置与审核材料**。
9. **端到端验收：真实账号、多儿童、导出删除、红旗安全、历史报告版本锁定**。

### P1 上线后首月必须补齐

1. 管理后台 UI（知识库、标准配置、删除工单、审计）。
2. 报告 PDF/图片分享与趋势图表。
3. 训练动作库增强、提醒、日历进度。
4. 受控 AI 文本咨询（带检索与拒答）。
5. iOS 发布链路。
6. 知识库人工上传工作流产品化；自动抓取可后置但需设计。

### P2 增强

1. 语音 ASR/TTS 与多模态咨询。
2. 设备端姿态推理与动态视频。
3. 多监护人精细权限。
4. 凌晨自动抓取权威源 + 候选审核。
5. 更完整的成长档案与长期对比。

当前 BOKS 项目已经完成从“文档 + 工程骨架”到“双端家长闭环可演示”的跨越，具备继续产品化的良好基础。但与**正式对外给家长使用**相比，仍差一整层生产系统：

1. **真身份**（不是 dev-login）；  
2. **真数据**（不是单家庭 JSON）；  
3. **真标准**（不是 demo 评分夹具）；  
4. **真媒体与算法**（不是照片 ID 登记）；  
5. **真运营与合规**（后台 UI、审计、协议、监控、发布）。

建议按本文阶段 0—10 继续推进，并在评分原文或姿态模型未就绪时主动收缩首发范围，确保先做“可信、可审核、可删除、非诊断”的正式产品，再扩展智能分析能力。
