# 07 UI 设计文档

## 1. 设计定位

主题色为果绿，传达活力、成长和自然；界面要安静、清楚、易读，不使用高刺激的成绩排名和恐吓式健康提示。学生看到的是动作目标，家长看到的是依据和行动，BOKS 内部审核员看到的是版本和证据。

## 2. 设计令牌

### 2.1 颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `color-brand-600` | `#2E8B57` | 主按钮、链接、选中态；深色背景上的文字 |
| `color-brand-500` | `#45A85B` | 主色、进度、插图 |
| `color-brand-300` | `#9BD88D` | 浅色背景、图表辅助 |
| `color-brand-100` | `#E9F7E7` | 卡片浅底、成功提示 |
| `color-ink-900` | `#173329` | 标题和正文 |
| `color-ink-600` | `#4C6258` | 次要说明 |
| `color-warning-600` | `#B56A00` | 需要复核的提示 |
| `color-danger-600` | `#B42318` | 红旗症状、停止训练 |
| `color-surface` | `#FFFFFF` | 卡片 |
| `color-canvas` | `#F7FBF6` | 页面背景 |
| `color-border` | `#D9E8DC` | 分隔线 |

正文和背景对比度必须达到 WCAG AA；不要使用浅果绿作为白色正文背景上的小字号文字。

### 2.2 字体和尺寸

- 中文优先系统字体：`PingFang SC`, `Microsoft YaHei`, sans-serif。
- 正文 16 px，辅助说明 13—14 px，按钮不小于 15 px。
- 标题层级：32/24/20/18 px；行高 1.35—1.6。
- 小程序使用 rpx 适配，但组件最小触摸尺寸不低于 44 × 44 px。

### 2.3 间距和圆角

```text
space-1 4px
space-2 8px
space-3 12px
space-4 16px
space-5 20px
space-6 24px
space-8 32px
radius-sm 8px
radius-md 12px
radius-lg 20px
```

页面采用 16 px 主边距；卡片内部 16—20 px；报告长页面用分组和锚点，不堆叠过多装饰。

## 3. 信息层级

### 3.1 家长首页

1. 儿童切换器和监护人授权状态；
2. “最近一次测量”和“下一步”；
3. 体测/体态两个主入口；
4. 训练今日任务；
5. 数据控制和咨询入口。

首页不直接展示“差/不及格”红色大字，使用“优先改善：耐力”这类行动语言。

### 3.2 体测录入页

- 顶部显示学段、年级、性别和标准版本；
- 每项使用 `label + 数值输入 + 单位 + 测量提示`；
- 体重/身高计算 BMI 时展示公式和“仅作体测指标”；
- 缺测、免测、补测使用清晰状态选择；
- 底部固定“保存草稿 / 检查并提交”；
- 提交前显示将生成报告的标准和版本。

### 3.3 体测报告页

结构：

```text
报告摘要
  总分/等级/测量日期/标准版本
优先行动
  3 个以内，按影响和可执行性排序
指标明细
  原始值 -> 单项分 -> 权重 -> 解释
趋势
  同一指标折线，标注测量条件
训练计划
数据来源与限制
```

图表必须提供数字列表和文字结论，不能只靠颜色。

### 3.4 体态拍摄页

- 用人体轮廓、脚位线和箭头说明，不使用吓人的脊柱图片；
- 每个视角只有一个动作目标；
- 质量失败显示“请把脚移到线内”“请移除外套遮挡”等具体建议；
- 显示“照片不能诊断疾病”；
- 原图上传前展示照片用途和删除入口。

### 3.5 体态报告页

- 顶部显示“姿态观察报告”而非“诊断报告”；
- 结果按“拍摄质量、观察到的表现、建议行动、何时就医”分组；
- 低置信度用“需要复拍/人工复核”，不能用确定性红色等级；
- 训练动作显示安全边界和停止按钮。

## 4. 组件规范

| 组件 | 状态 |
| --- | --- |
| `PrimaryButton` | 默认、按下、禁用、加载、危险确认 |
| `ChildSelector` | 单儿童、多个儿童、无档案、切换确认 |
| `MetricInput` | 空、输入中、合法、越界、缺测、免测 |
| `ScoreCard` | 总分、无总分（幼儿参考）、加载、失败 |
| `QualityFeedback` | 通过、失败原因、多原因、不可恢复 |
| `EvidenceChip` | 标准名称、版本、官方来源、展开详情 |
| `TrainingCard` | 待开始、进行中、完成、暂停安全复核 |
| `ConsentSheet` | 初次同意、已同意、撤回、版本更新 |
| `ReportSection` | 折叠/展开、引用、限制说明 |

## 5. 状态和文案

### 5.1 文案规则

- 说“观察到”“提示”“建议复核”，不说“患有”“确诊”。
- 说“本次数据对应 2014 年修订标准”，不说“国家最新分数”除非知识库明确证明。
- 说“体测项目未完成”，不说“0 分”。
- 说“停止训练并尽快就医”，不说“严重问题”。
- AI 不确定时说“我无法根据现有信息判断”，并给出下一步。

### 5.2 错误文案

错误包括原因、影响和操作：

> “未检测到完整人体。请保持手机与地面平行，站在脚位线内，重新拍摄。你也可以跳过体态分析，继续录入体测数据。”

## 6. 无障碍和儿童可用性

- 颜色不是唯一的状态表达，配合图标和文字；
- 支持系统字号放大，布局不截断；
- 语音播报和文字同步；
- 动画可关闭，避免快速闪烁；
- 训练动作提供图文、短视频和文字版；
- 确认删除、撤回、就医提示使用家长门；
- 儿童完成打卡后显示鼓励，不显示与同龄人排名。

## 7. 动效

- 页面转场 200—280 ms；
- 分析进度使用柔和的呼吸动画，不表示医疗准确率；
- 训练完成使用轻量果绿反馈；
- 风险提示不使用震动、闪烁或红色全屏恐吓；
- 尊重系统“减少动态效果”设置。

## 8. 设计交付物

- Figma 组件库和变量；
- 小程序/App/后台三端页面流；
- 四视角拍摄姿态图和错误示例；
- 报告空态、加载、错误、低置信度和删除状态；
- 标准来源展开页；
- 中英文/数字/长文本溢出测试；
- 开发标注：尺寸、颜色、交互、埋点和无障碍标签。

## 9. UI 验收

- [ ] 所有主操作可在单手和放大字体下完成。
- [ ] 所有图表有文字/数字替代。
- [ ] 体态页面突出非诊断限制和监护人控制。
- [ ] 颜色对比度达标，浅果绿不用于小字号正文。
- [ ] 失败状态给出可执行动作，不出现“系统错误”空文案。
- [ ] 训练暂停、就医提示和删除确认不被误触。
